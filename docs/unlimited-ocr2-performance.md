# Unlimited-OCR-2 性能与部署验证（2026-10-28）

实机：Windows、RTX 5070 Ti 16GB、Docker Linux 容器。两个后端使用同一个固定的
Unlimited-OCR-2 revision，分别独占 GPU。结果来自本项目公共流式 API，包含渲染、
推理和结果整理，不包含下载、加载权重与首次内核编译；输入文件已准备在本地。
测试没有上传文档到外部服务。以下是单次观测，不是多轮统计或通用准确率基准。

## 两个后端的热启动结果

| 输入 | Transformers | SGLang CUDA Graph | 返回页数 |
| --- | ---: | ---: | ---: |
| 单页图片 | 21.000 秒 | 1.719 秒 | 1 |
| 合成双页 PDF（中英、表格、公式） | 35.781 秒 | 2.187 秒 | 2 |
| 密集扫描 PDF 两页 | 124.172 秒 | 7.485 秒 | 2 |
| 密集扫描 PDF 五页 | 383.156 秒 | 19.750 秒 | 5 |
| 双页 Office 转换后的 PDF | 50.265 秒 | 1.375 秒 | 2 |

Office 转换发生在计时前。表中 SGLang 测试采用最终保护检查节流逻辑；随后为修复
长文档跨窗口阻塞，将内部请求槽和 decode graph 最大批次从 1 调整为 2。
独立直接请求的 SGLang 解码观测约为 213–217 token/s，不等同于整份文件的平均吞吐。
Transformers 与 SGLang 对 EOS 的 token 计数相差 1，不用于判断正文缺失。

五组输入的两个后端 Markdown 完全相同，逐页布局块数量相同。检查了中英文、
表格字段、公式与分页返回；这不能替代更广泛的文档准确率测评。

## 异常慢速与跨页修复

- 官方 `/health` 会生成一个 token，频繁轮询出现的极低吞吐日志不是文档解码速度。
  适配器和容器健康检查改用 `/ready`，关闭该健康端点生成。
- 启用完整 prefill/decode CUDA Graph，预填充桶 1024/2048，
  `full_prefill_max_req=1`，decode 最大批次 2，graph 元数据输入和刷新设为 1。
- 第十页内部窗口结束后，官方调度器保留 KV 和请求槽。只配置一个槽会让下一窗口
  无法运行。改为两个内部槽，仍限制一个公共 OCR 作业。
- 逐 token 重扫完整输出的重复检测产生 CPU 尾部积压。检查改为新增 128 字符或
  250ms 后执行，并始终检查最后一段；保留异常重复和截断保护。
- PDF 在渲染前约束最长边 2048，避免大尺寸扫描页按 300dpi 产生不必要的像素开销。
- 加载模型的后台任务共享，取消请求不会启动第二份加载；推理线程退出后才释放锁，
  防止取消、切换或卸载交错。重复取消和 AnyIO 取消已通过隔离回归测试。

最终两个内部槽配置的真实密集 12 页测试：**57.828 秒，11030 输出 token，
12 页、22138 个 Markdown 字符，正常 stop，无接口错误**。逐页布局块数为
`15,40,17,8,29,27,41,39,36,36,34,28`，已跨过第十页窗口。
早先单槽的同一测试停在第十页，不能将其标为成功。

独立自动入口重新部署后的最终配置复测：双页流式 2.063 秒、五页流式 19.453 秒、
双页同步 2.204 秒，均正常 stop，正文与 Transformers 对应结果完全相同。
浏览器实际上传双页 PDF，按每批 5 页配置一次提交并完成两页；中英、表格、公式均显示，
无浏览器 error 日志，左侧 PDF 按容器宽度缩放。该自建网页测试任务验证后已精确清理，
用户原有 24 页任务保留，源文件哈希与测试前一致。

## 自动部署适配范围

独立命令为 `unlimited-ocr2-one-click.bat`。启动器验证 GPU 架构、显存、驱动、
Docker Linux 容器及内存，并实际执行 BF16 CUDA 运算。多显卡支持自动选择及 `-GpuId`。

| 档位 | 自动后端 | 上下文 | 输出预算 | 默认每批页数 |
| --- | --- | ---: | ---: | ---: |
| 12GB | Transformers | 16384 | 8192 | 2 |
| 16GB | SGLang | 32768 | 28672 | 5 |
| 24GB 及以上 | SGLang | 65536 | 57344 | 10 |

自动入口要求 sm80+、Windows NVIDIA 驱动 580.88+、Docker 至少 8GiB 内存。
12GB 档不开放 SGLang。旧 GPU、非 NVIDIA 或 CPU 设备会收到原因和原有 CPU 模型/
外部服务入口提示。原来的其他模型部署方式和统一界面继续保留。

16GB SGLang 静态显存比例 0.65，24GB 档 0.70。实测 16GB 图配置总显存占用约
13GB（包含桌面等进程）；按实际空闲显存检查，不能只看显卡名称。
本项目已有模型占用显存时，由控制器完整停止并检查释放后再加载。

当前真实硬件验收只有上述 5070 Ti。12GB、24GB、旧架构、旧驱动、显存不足及多卡
映射通过策略/协议测试，尚未在对应硬件完成实机验收。当前机器验证使用已有镜像
和权重的 `-SkipBuild -SkipPull` 部署路径；全新电脑首次下载、构建仍需另行验收。
Windows 绑定目录读取权重和首次编译可能耗时数分钟，与热启动识别速度应分开报告。

每批请求仍受 50 页、60000000 渲染像素和输出预算保护。不同 WebUI 批次不共享
模型上下文；同一请求内的官方多窗口路径已用上述 12 页验证。
详细参数与入口见[部署说明](unlimited-ocr.md)。
