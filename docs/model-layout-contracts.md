# 各模型文档结构适配约定

版面类别不是跨模型统一标准。原生类型、阅读顺序、坐标空间、公式及图像表示应按模型适配；中文标签只负责显示，不能反向改写原始类型。

| 模型族 | 原生输出 | 适配边界 |
|---|---|---|
| PaddleOCR-VL | PaddleX 文档流水线的 `layoutParsingResults`、`parsing_res_list` 与 Markdown；本地配置为 PP-DocLayoutV3 | 保留上游标签、顺序和 Markdown；不按 Ovis 类别白名单过滤。用户显式设置的上游识别／忽略参数与本地后处理分开 |
| PP-OCRv6 | 文字行、置信度、四边形／矩形框 | 保留 `ocrLines` 和逐行定位，不虚构标题、图片、公式等版面分类 |
| OvisOCR3 | 官方 24 类结构化 JSON；四类视觉区块、LaTeX 公式、HTML 表格与 Markdown | 使用专门的内容约定；源 PDF 校正必须逐块验证，无法绑定则保留模型结构；详见 [24 类约定](../OVISOCR3_CAPABILITIES.md) |
| HPD-Parsing | `<BLOCK>`、类型、坐标和 `<CHILD>` 内容 | 按其原生类型处理标题、正文、公式与图像；保留段落、表格 HTML 和边缘文字，空内容的印章等视觉区域保留源图 |
| Unlimited-OCR-2 | 文档检测标记、开放类别及标题层级标记 | 保留开放类别和层级，不限定为 Ovis 的 24 类；保留代码缩进与页眉页脚，不把检测标记解释规则套到其他模型的正文 |
| NaviDC-OCR | 固定 24 类区块、角度及原始内容 | 原生类别包含 `char`（科学图示）、`phonetic`、`equation_block` 等，与 Ovis 的 24 类不同；保留原始区块及视觉区域文字 |

## 共用层的职责

1. 根据区块／页面的原生解析器、任务模型确定中文名称。界面切换到另一个模型后，历史任务仍使用原所属模型的解释。
2. Markdown 保留段落、列表、代码围栏、链接、表格、公式和图像说明。脚注与注音等类型的流式显示不等同于像素级版式复刻。
3. 公式渲染跳过 `pre`、`code` 等代码内容。HTML 表格保留标题和合并单元格；代码示例中的 HTML 不解释成实际表格。
4. 图片按原始标识或各模型的视觉区块顺序关联，避免把页眉图片关联到表格或前一个图表。缓存中的逐页图片名与批次资源名必须解析到同一资源。
5. 原始类别、模型输出及坐标保留。派生展示和显式跨页表格合并记录来源；人工修改不能被自动恢复覆盖。

## 验证范围

各适配器及前端使用各自类别和标记的受控样例进行回归，验证后处理保留结构。PP-OCRv6 按文字行结构验收。Ovis 另覆盖完整 24 类 HTTP 自动解析、缓存增强、原生 PDF、浏览器中文标签、实际下载和本机真实权重的 HTTP 冒烟测试。

受控输出测试不代表模型识别准确率，也不代表所有模型在本机硬件上都完成了真实推理。当前运行模型的实际服务验证与其他模型的适配器测试应分别报告。
